# ROS Package [bob_mossimg](https://github.com/bob-ros2/bob_mossimg)

ROS 2 node for the **MOSS-Image-SFT** text-to-image model from OpenMOSS (Apache 2.0).

## Supported Models

- **[MOSS-Image-SFT](https://huggingface.co/OpenMOSS-Team/MOSS-Image-SFT)** (default): Supervised fine-tuned checkpoint, Apache 2.0.
- **[MOSS-Image-Base](https://huggingface.co/OpenMOSS-Team/MOSS-Image-Base)**: Base checkpoint.

Switch via the `repo_id` ROS parameter or the `MOSSIMG_REPO_ID` environment variable. The model uses a **custom diffusers pipeline** (`custom_pipeline="pipeline_moss_image"`, `trust_remote_code=True`); the pipeline code and weights (~27 GB) are downloaded automatically into `model_dir`.

> [!NOTE]
> MOSS-Image understands plain prompts, tag sequences and **JSON layout prompts** (rendered text and object placement via `bbox_format: "yxyx"`), see the [user guide](https://github.com/OpenMOSS/MOSS-Image/blob/main/USERGUIDE.md). Python-API image dimensions must be positive multiples of 16.

## Installation & Build

### 1. Clone the repository
```bash
cd ~/ros2_ws/src
git clone https://github.com/bob-ros2/bob_mossimg.git
```

### 2. Install dependencies
It is recommended to use a virtual environment.
```bash
pip install -r bob_mossimg/requirements.txt
```

### 3. Build the workspace
```bash
cd ~/ros2_ws
colcon build --packages-select bob_mossimg
source install/setup.bash
```

## Usage

### Run the node
```bash
ros2 run bob_mossimg tti --ros-args --params-file src/bob_mossimg/config/tti.yaml
```

### Send a prompt
```bash
ros2 topic pub /mossimg/prompt std_msgs/msg/String "{data: 'A futuristic city in the style of cyberpunk'}" --once
```

### JSON Prompt Support
The node automatically detects plain text or a JSON string. Unknown JSON keys are ignored with a warning.

**Per-request parameter overrides**: the dynamic parameters can be overridden for a single request directly in the JSON body; wrong types are ignored with a warning and the ROS parameter values apply:

| JSON key | Type | Replaces ROS parameter |
| :--- | :--- | :--- |
| `seed` | int | `seed` (`-1` = random) |
| `num_inference_steps` | int | `num_inference_steps` |
| `guidance_scale` | number | `guidance_scale` |
| `num_images_per_prompt` | int | `num_images_per_prompt` |
| `max_sequence_length` | int | `max_sequence_length` |
| `uncond_skip_layers` | int list | `uncond_skip_layers` (`[]` disables) |
| `height` / `width` | int | `height` / `width` (multiples of 16) |

**Example:**
```json
{
  "content": "A high-quality photo of a cat",
  "num_inference_steps": 20,
  "guidance_scale": 2.5,
  "seed": 42,
  "height": 768,
  "width": 1024
}
```

## ROS API

### Topics

| Topic | Message Type | Direction | Description |
| :--- | :--- | :--- | :--- |
| `/mossimg/prompt` | `std_msgs/msg/String` | **Sub** | The input prompt for text-to-image generation. |
| `/mossimg/generated_image` | `sensor_msgs/msg/Image` | **Pub** | The resulting image, published in `bgr8` encoding. |

### Parameters

#### Dynamic Parameters

| Parameter | Env Variable | Default | Description |
| :--- | :--- | :--- | :--- |
| `keep_loaded` | `MOSSIMG_KEEP_LOADED` | `false` | If true, keeps the model in memory. |
| `cpu_offload` | `MOSSIMG_CPU_OFFLOAD` | `true` | If true, uses model CPU offloading. |
| `sequential_offload` | `MOSSIMG_SEQUENTIAL_OFFLOAD` | `false` | Aggressive offloading for very tight VRAM. |
| `num_inference_steps` | `MOSSIMG_NUM_STEPS` | `50` | Denoising steps (flow-matching Euler). |
| `guidance_scale` | `MOSSIMG_GUIDANCE` | `3.0` | CFG strength. |
| `num_images_per_prompt` | `MOSSIMG_NUM_IMAGES` | `1` | Batch generation count. |
| `max_sequence_length` | `MOSSIMG_MAX_SEQ` | `4096` | Max prompt length. |
| `uncond_skip_layers` | `MOSSIMG_UNCOND_SKIP_LAYERS` | `[22]` | Negative-branch layers replaced by skipped-block prediction (empty to disable). |
| `frame_id` | `MOSSIMG_FRAME_ID` | `mossimg` | The frame_id for the output. |

#### Static Parameters

| Parameter | Env Variable | Default | Description |
| :--- | :--- | :--- | :--- |
| `repo_id` | `MOSSIMG_REPO_ID` | `OpenMOSS-Team/MOSS-Image-SFT` | Model repository ID. |
| `model_dir` | `MOSSIMG_MODEL_DIR` | `./models` | Cache directory. |
| `device` | `MOSSIMG_DEVICE` | `cuda:0` | Computing device. |
| `prompt` | `MOSSIMG_PROMPT` | `''` | Initial prompt at startup. |
| `seed` | `MOSSIMG_SEED` | `-1` | Random seed (-1 for random). |
| `image_path` | `MOSSIMG_IMAGE_PATH` | `''` | Output path; empty disables local saving. |
| `once` | `MOSSIMG_ONCE` | `false` | Exit after first generation if true. |
| `height` | `MOSSIMG_HEIGHT` | `1024` | Image height (multiple of 16). |
| `width` | `MOSSIMG_WIDTH` | `1024` | Image width (multiple of 16). |
| `image_counter_start` | `MOSSIMG_IMAGE_COUNTER_START` | `1` | Start value for autogenerated filenames. |

## Docker

```bash
cd ros2_ws/src/bob_mossimg
docker compose up -d --build
docker logs -f bob_mossimg    # first start downloads the model into ./models (~27 GB)
```

> The container runs as `user: 1000:1000` (the host user `ros`) so the FastDDS shared-memory transport works with host processes (`ipc: host`). For a different host user, set `MOSSIMG_UID`/`MOSSIMG_GID` in `.env`.

Send a prompt (the container shares the host network; `ROS_DOMAIN_ID=55`):
```bash
ros2 topic pub /mossimg/prompt std_msgs/msg/String "{data: 'A futuristic city in the style of cyberpunk'}" --once
```

## Configuration File

An example configuration file is provided at `config/tti.yaml`. It contains all parameters with descriptions.

## Hardware Optimization

The node is optimized for NVIDIA consumer GPUs (like the RTX 4090) using bfloat16 for transformer and text encoder and float32 for the VAE. `cpu_offload: true` (default) enables `enable_model_cpu_offload()` so it can coexist with other GPU-intensive nodes; `sequential_offload: true` trades speed for minimal VRAM. 50 steps at 1024×1024 with CFG takes roughly a minute on an RTX 4090.

> **Multiple image nodes on one GPU:** the default is `keep_loaded: false` — the model is loaded per request from the page cache (~3 s) and then evicted from VRAM entirely, so `bob_mossimg` and `bob_flux3k` can coexist on one card. Two generations running at the same time still do not fit in 24 GB — drive requests sequentially. Topics live under `/mossimg/…` so the nodes never trigger each other.
